# 历史开发记录

以下保留原 README 的回归步骤和实现细节，部分描述属于引擎迁移前的版本。当前目录和职责以 [架构规范](../ARCHITECTURE.md) 为准；兼容性与测试结论见 [验证记录](COMPATIBILITY.md)。

## 音量代理回归检查

更新驱动并重启 coreaudiod 后，检查：

1. 默认输出选择内建扬声器，用音量键、静音键和 Sona 主滑块调节；系统音量显示与设备音量一致。
2. 在“音频 MIDI 设置”中修改真实设备音量，Sona 主滑块同步更新。
3. 切换到另一个输出设备，显示该设备原本的音量，不把旧设备音量写入新设备。
4. 连续按音量键，确认不会回跳；拔插默认输出设备后检查恢复。
5. 为某个应用单独选择另一个输出设备，调整默认输出音量／静音，确认独立输出不受影响。
6. 对不支持硬件音量的设备，确认数字音量回退仍然可用。


## 应用列表与发声检测

驱动在逐进程音量处理前检测非静音音频样本（阈值 -120 dBFS），不再把启动音频通道或历史播放记录视为正在发声。有音频 IO 时，独立的非实时队列每 50 ms 检查状态变化并通知应用；停止输出信号约 300 ms 后隐藏条目，以避免短暂停顿时闪烁。实际显示延迟还受系统调度影响。

静音应用的音量、路由设置仍会保存并应用到其辅助进程。在 Sona 内调低音量或静音不会让仍在输出音频的应用消失，便于恢复声音；应用自身暂停或输出静音样本才会隐藏。系统服务和系统提示音仅从列表中排除，不改变它们的播放。

此功能需要同时更新 App 和驱动。验证时打开菜单，检查音乐播放／暂停／恢复、Safari 标签页播放、已设置音量应用恢复播放，以及系统提示音不出现。


## 后台开销

- 无音频 IO 时，发声检测定时器停用；StartIO 后立即恢复 50 ms 检测。仍保持 IO 的静音应用继续检测，避免恢复播放时延迟显示。
- 输出设备只在有运行中的音频客户端路由到它时启动；最后一个使用者停止 IO 或切走路由后延迟 2 秒停机。短暂停顿恢复会取消停机。保存的路由本身不会让闲置设备开始运行；保持 IO 的应用仍保留其输出设备。
- App 依靠驱动／设备事件及时更新，兜底轮询由 1.5 秒降为 15 秒，允许 3 秒容差。移除每轮连接日志，仅在状态变化时发布连接、主音量等属性。

`make test` 覆盖默认／多设备路由需求、闲置设备不启动、延迟停机取消、最后一个 IO 停止后定时器停用，以及重新开始 IO 后恢复检测。节电幅度尚未实测；应在同样的设备和播放内容下对比 Sona 与 Core Audio 宿主进程的 CPU、唤醒次数和能耗，并确认无爆音／丢帧。

- 音量／静音配置变化直接更新客户端增益，保留配置持久化；仅默认输出或应用路由变化才重新检查设备和路由。设备热插拔仍由设备列表通知触发完整检查。


## 音频转换质量（驱动 0.3.0）

- 使用 128 零交叉半宽的 Blackman–Harris 加窗 sinc 滤波器，1024 倍精度的预计算系数表；根据源／目标采样率缩放截止频率，降采样时抑制混叠。共享表约 512 KiB，在配置队列初始化，实时线程不分配内存、不计算三角函数、不调用 HAL。
- 缓冲水位经过约 2 秒低通后送入 PI 时钟跟踪器，修正上限 ±500 ppm（±0.05%），变化速度上限每秒 20 ppm。不同输出设备各自维护相位、滤波历史和时钟状态。它仍是基于缓冲水位的估计，不是硬件时间戳同步。
- 缓冲不足、溢出和采样率切换时重置滤波历史与时钟跟踪，短淡出／淡入后重新缓冲，不用大幅变速追回延迟。保留约 2048 源帧的基础预缓冲；大回调会增加预缓冲，滤波历史也增加少量延迟。
- 保留逐应用音量、静音、路由、硬件主音量以及多设备输出；此版本仍非 bit-perfect，也不保证多个设备采样级同步。没有加入单设备直通。

运行 `make test-audio` 验证频率响应、混叠抑制、声道隔离、10 分钟模拟播放和时钟漂移；`make test` 验证原有控制／路由行为。测试是离线合成信号，不代表所有歌曲、硬件、蓝牙或系统调度条件；实机音质、回调时限和能耗仍需安装后验证。


## 时钟跟随与直通（驱动 0.4.0）

- 默认输出设备的 IOProc 每个周期发布自己的（host time，sample time）锚点；Sona 的 `GetZeroTimeStamp` 据此放置零时间戳，只取设备的速率，不做偏移跳变，每周期调整幅度限制在 ±2000 ppm 内。没有锚点（设备未启动、停摆、刚切换）时按 host time 自由运行，时间线始终单调连续。
- 锁定后，默认输出与 Sona 采样率一致时进入直通：环形缓冲逐帧拷贝，不经过 sinc 滤波和 PI 控制器，延迟只剩约 512 帧抖动余量加一个回调周期加一个生产者周期。硬件主音量可用且只有一个应用以 1.0 增益播放时，输出与输入 bit 相同；多应用混音或数字增益仍是浮点运算，但没有重采样失真。
- 失锁、采样率不一致、设备重启（sample time 重置）、断流都会淡出并回到重采样路径重新预缓冲。单独路由到其他设备的应用不受影响，那些设备仍各自重采样。
- `snst` 状态每个目标新增 `passthrough` 和 `clockLocked` 两个布尔值，用于确认实机是否真的走了直通。
- 已知取舍：Sona 设备在系统看来的实际速率会偏离标称值几十到几百 ppm（等于默认设备晶振的偏差），这正是跟随时钟的含义。默认设备切换时会有一次短淡出。

`make test` 里的时钟锁定用例用假时钟验证 Sona 时间线在 120 秒内跟到设备的 200 ppm 偏差、失锁后回到标称速率、设备重启后重新锁定且时间戳不倒退；`make test-audio` 里的直通用例验证淡入后 2000 个周期逐样本 bit 相同、延迟恒定、失锁／采样率不一致／断流时的回退。实机需检查 `log show` 无 underrun、状态里 `passthrough` 为真，以及切换默认设备时不爆音。


## 多设备独立音量（驱动 0.5.0）

- 单设备保留原来的紧凑音量条；当前应用选用多个已连接设备时，顶部展开「输出设备」卡片，每个设备显示名称、音量百分比、滑块和独立静音。默认设备排在第一行，标注「默认」，右侧菜单可切换默认输出。
- 应用音量作用于该应用的全部输出；顶部每个设备的音量作用于该设备收到的全部应用声音。键盘音量键仍只控制默认输出。
- 各设备优先使用可写硬件音量／静音，按声道控制时保留声道平衡；缺少某项硬件控制时，仅该项使用数字回退，不会叠加两次音量衰减。数字音量／静音按设备 UID 保存到驱动存储，切换默认设备、移除路由或重启后恢复。
- 设备自身音量变化通过 HAL 通知同步到界面。旧驱动仍能控制默认设备，额外设备音量需同时升级驱动；准备中或不支持的控制会禁用。

验证：`make test` 覆盖真实混音路径的输出隔离、独立静音、外部硬件音量同步、写入／读取失败、默认设备角色切换、非法命令和驱动存储恢复；`make test-audio` 检查音频处理回归。实机需在更新 App 和驱动后，用两个输出设备同时播放，分别拖动音量及静音，再切换默认输出和使用键盘音量键确认行为。


## 非默认设备滑块响应（0.5.1）

拖动先更新 App 本地值，HAL 写入与状态读取移到后台串行队列。App 按 30 Hz 合并各设备的最新音量，驱动也按 UID 合并尚未执行的命令，慢速硬件不会堆积过时位置。拖动期间保留手指位置，松开后发送最终值，等待 1 秒让硬件状态稳定，再恢复实际音量同步（包含设备量化或写入失败）。

`make test-app` 验证连续拖动、慢传输期间的新输入、设备隔离和最终值发送；`make test` 新增阻塞驱动队列下 501 次拖动合并为一次硬件调节的回归测试。需要同时更新 App 和 0.5.1 驱动以获得完整修复。
